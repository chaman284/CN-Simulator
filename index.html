Protocol Mechanics
Stop-and-Wait ARQ

One-Bit Protocol

Single in-flight frame. Alternating 0/1 sequence numbers. Simplest reliable delivery.

Window: 1 Individual ACK No pipelining
  • Window size is strictly 1 unacknowledged frame at any time.
  • Alternating sequence numbers 0 and 1 detect duplicates on retransmit.
  • Sender halts until an ACK arrives before transmitting the next frame.
  • On timeout or ACK loss, the same single frame is retransmitted.
  • No pipelining — lowest utilisation on high-latency links.
Sequence space2 (0, 1)
Receiver buffer1 frame
Retransmit scopeCurrent frame only
Case 1 Normal operation

Frame 0 sent → ACK 1 received → Frame 1 sent. Clean alternating bits without channel loss or timeouts.

Case 2 The frame is lost

Frame is dropped by the link. Sender timer expires and automatically triggers a retransmission of the lost frame.

Case 3 The ACK is lost

Frame delivered, but ACK lost in transit. Sender times out; receiver detects duplicate sequence, discards data, and re-sends ACK.

Case 4 The ACK is delayed

Channel delay exceeds sender timeout. Sender prematurely retransmits; delayed ACK arrives later and duplicate is safely absorbed.

Sliding Window ARQ

Go-Back-N

Cumulative ACKs. Full window rollback on any loss. High throughput on clean links.

Window: N Cumulative ACK Discard OOO
  • Sender may have up to N frames in flight simultaneously (pipelined).
  • Receiver accepts only the next expected frame in strict sequence.
  • Out-of-order frames are discarded, even if received without error.
  • ACK k is cumulative — confirms all frames up to and including k.
  • On timeout, sender rolls back and retransmits all unACKed frames.
Sequence space2N (min)
Receiver buffer1 frame
Retransmit scopeAll unACKed frames
Case 1 Normal operation

Continuous pipelined transmission within window N. Cumulative ACKs smoothly slide the sender base forward.

Case 2 The frame is lost

Frame lost in flight. Receiver discards subsequent out-of-order frames. Sender times out and rolls back to retransmit window.

Case 3 The ACK is lost

Intermediate ACK lost, but subsequent cumulative ACK arrives safely. Cumulative ACKs absorb losses without rollback.

Case 4 Delayed ACK / Timeout

High channel delay causes base frame timer expiry. Sender rolls back and retransmits all unacknowledged frames.

Selective ARQ

Selective Repeat

Receiver buffers out-of-order frames. Only lost frames are retransmitted.

Window: N Individual ACK Buffers OOO
  • Both sender and receiver maintain an independent N-frame window.
  • Receiver buffers out-of-order frames that fall within its window.
  • Individual ACK sent for each correctly received frame (not cumulative).
  • Sender retransmits only the specific timed-out frame, not all unACKed.
  • Minimal redundant transmission — most efficient on lossy links.
Sequence space2N (required)
Receiver bufferN frames
Retransmit scopeLost frame only
Case 1 Normal operation

Sender pipelines N frames; receiver individually ACKs each. Windows advance independently as frames arrive.

Case 2 The frame is lost

Frame lost in transit. Receiver buffers subsequent frames. Sender retransmits ONLY the lost frame, avoiding redundant retransmission.

Case 3 The ACK is lost

Individual ACK lost. Only that frame times out; sender selectively retransmits it without re-sending already-ACKed frames.

Case 4 Window Constraint

Demonstrates why window size cannot exceed half sequence space (W ≤ 2^(m-1)) to avoid duplicate wrap-around ambiguity.
